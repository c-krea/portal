01 — Contexto

¿Qué estamos construyendo?

El Portal C-Krea necesita datos del ERP CSF (pagos, cartera, contratos) para reemplazar el proceso manual de Excel. La API del ERP vive en una IP privada que Vercel no puede alcanzar directamente, así que acordamos la arquitectura más segura: IT corre un script desde dentro de la red y empuja los datos a nuestra base de datos Supabase. Vercel luego lee de Supabase normalmente — sin tocar el ERP jamás.

02 — El problema actual

Por qué falla la conexión

El script ya usa el formato correcto de usuario (siesa_sync.bosylehvmtwtqkrlievy — necesario para el pooler de Supabase). Pero la contraseña contiene caracteres especiales (&, !, *) que rompen el parsing cuando se pasan como URL. Python lee solo la parte antes del primer & y envía una contraseña incompleta.

MétodoResultado
❌ Falla psycopg2.connect("postgresql://siesa_sync.xxx:r2A&Y!...@host:6543/postgres") Python corta la contraseña en & → credenciales inválidas → Tenant or user not found
✓ Funciona Pasar cada parámetro por separado con host=, password=, etc. Python no interpreta la contraseña como URL — caracteres especiales llegan intactos
03 — Código de prueba

Script para verificar la conexión

Copiar y ejecutar. Si imprime "Conexion OK" y un número mayor a 0, todo está funcionando correctamente.

import psycopg2 # ── Datos de conexión ─────────────────────────────────────────────── DB_HOST = "aws-0-us-east-1.pooler.supabase.com" DB_PORT = 6543 DB_NAME = "postgres" DB_USER = "siesa_sync.bosylehvmtwtqkrlievy" # sufijo obligatorio para el pooler DB_PASSWORD = "[CONTRASEÑA_ENTREGADA_POR_GERMAN]" # no poner en URL — usar este parámetro # ── Prueba de conexión ────────────────────────────────────────────── def test_connection(): try: conn = psycopg2.connect( host=DB_HOST, port=DB_PORT, dbname=DB_NAME, user=DB_USER, password=DB_PASSWORD, sslmode="require" # Supabase requiere SSL ) cur = conn.cursor() # Prueba 1: ¿conecta? cur.execute("SELECT NOW();") print("✓ Conexion OK:", cur.fetchone()[0]) # Prueba 2: ¿puede leer payments? cur.execute("SELECT COUNT(*) FROM payments;") count = cur.fetchone()[0] print(f"✓ Tabla payments accesible: {count} registros") # Prueba 3: ¿puede leer cartera? cur.execute("SELECT COUNT(*) FROM cartera;") print(f"✓ Tabla cartera accesible: {cur.fetchone()[0]} registros") conn.close() print("→ Listo. Conexion y permisos verificados.") except Exception as e: print("✗ Error:", e) test_connection()
Nota sobre la contraseña

La contraseña real será enviada por German por un canal seguro (no por este documento). Reemplazar [CONTRASEÑA_ENTREGADA_POR_GERMAN] con el valor recibido — siempre como parámetro separado, nunca dentro de la URL.

04 — Tablas y campos

Qué debe escribir el script en Supabase

El script consume tres endpoints del ERP y escribe en tres tablas de Supabase. La lógica es siempre upsert: si el registro ya existe se actualiza, si es nuevo se inserta. Nunca se eliminan registros — la base de datos mantiene historial completo.

Comportamiento del upsert

✓ Registro nuevo → se inserta.

✓ Registro existente con datos iguales → se omite (sin cambios).

✓ Registro existente con datos diferentes → se actualiza.

✓ Correr el script múltiples veces es seguro — nunca crea duplicados.

05 — Referencia rápida

Errores más comunes

Si el script lanza un error, esta tabla cubre los casos más frecuentes:

ErrorCausa probableSolución
Tenant or user not found Usuario en la URL sin sufijo del proyecto, o contraseña cortada por & Usar parámetros separados (host=, password=) — nunca URL. Usuario debe ser siesa_sync.bosylehvmtwtqkrlievy
password authentication failed Contraseña incorrecta o copiada con espacios extra Verificar que la contraseña esté copiada exactamente, sin espacios al inicio o final
SSL connection required Falta el parámetro sslmode Agregar sslmode="require" a la conexión
permission denied for table X El rol siesa_sync no tiene acceso a esa tabla específica Avisar a German — se agrega el permiso en Supabase en minutos
connection refused / timeout Puerto bloqueado por firewall local, o host incorrecto Verificar que el host sea exactamente aws-0-us-east-1.pooler.supabase.com y puerto 6543. Probar con puerto 5432 (conexión directa) para descartar firewall
column X does not exist Nombre de columna incorrecto en el INSERT/upsert Revisar la tabla de mapeo en la sección 04 de este documento — los nombres en Supabase pueden diferir de los del ERP
Script conecta pero COUNT(*) = 0 El rol siesa_sync puede conectar pero no ver filas (RLS activo) Avisar a German — se verifica que RLS permita acceso al rol
