Fix: Error de conexion Supabase

Causa identificada y solución aplicada  |  Portal C-Krea  |  Abril 2026

1. El error que aparecio

Al intentar conectar el job de sincronizacion con Supabase usando el usuario siesa_sync, Python devolvio este error:

psycopg2.OperationalError: connection to server at "aws-0-us-east-1.pooler.supabase.com" (52.45.94.125), port 6543 failed: FATAL: Tenant or user not found
connection to server at "aws-0-us-east-1.pooler.supabase.com" (52.45.94.125), port 6543 failed: FATAL: Tenant or user not found
Conclusion rapida

El usuario siesa_sync existe y tiene los permisos correctos. El problema es unicamente el formato del nombre de usuario en la cadena de conexion — le falta el sufijo del Project ID.

2. Por que ocurre este error

Supabase usa un componente llamado PgBouncer como pooler de conexiones (puerto 6543). Su funcion es recibir muchas conexiones simultaneas y distribuirlas eficientemente hacia la base de datos real, evitando abrir y cerrar conexiones costosas con cada peticion — ideal para jobs frecuentes y aplicaciones con trafico alto.

El problema es que este pooler atiende miles de proyectos Supabase distintos en el mismo servidor fisico. Para saber a cual proyecto pertenece cada conexion entrante, necesita que el nombre de usuario incluya el Project ID del proyecto. Si llega solo el nombre de usuario sin el sufijo, el pooler no puede identificar el destino y responde con Tenant or user not found.

Regla del pooler de Supabase (puerto 6543)

El nombre de usuario siempre debe tener este formato:

nombre_usuario.project_id

El Project ID de este proyecto es bosylehvmtwtqkrlievy.

3. Que verificamos

Para descartar otras causas, consultamos directamente la base de datos y confirmamos que el rol existe y esta configurado correctamente:

Campo verificadoValorEstado
Rol siesa_sync existe Si OK
Puede hacer login (rolcanlogin) true OK
No es superusuario (rolsuper) false OK — correcto por seguridad
Formato usuario en connection string siesa_sync (sin sufijo) ERROR — falta el Project ID

4. La correccion

Cambiar el nombre de usuario en la connection string, agregando .bosylehvmtwtqkrlievy al final:

Connection string
❌ Antes postgresql://siesa_sync:[PASSWORD]@aws-0-us-east-1.pooler.supabase.com:6543/postgres
✓ Ahora postgresql://siesa_sync.bosylehvmtwtqkrlievy:[PASSWORD]@aws-0-us-east-1.pooler.supabase.com:6543/postgres

Opcion A — Pooler (recomendada, alta frecuencia):

postgresql://siesa_sync.bosylehvmtwtqkrlievy:[PASSWORD]@aws-0-us-east-1.pooler.supabase.com:6543/postgres

Opcion B — Conexion directa (sin pooler, usuario sin sufijo):

postgresql://siesa_sync:[PASSWORD]@db.bosylehvmtwtqkrlievy.supabase.co:5432/postgres
Que cambia y que no cambia

✓ Contrasena: igual, sin cambio.

✓ Host y puerto: igual, sin cambio.

✓ Permisos del rol: igual, sin cambio.

→ Solo cambia el nombre de usuario en la URL de conexion.

5. Cual opcion usar

OpcionPuertoCuando usar
A — Pooler 6543 Job que corre varias veces al dia, aplicaciones con multiples conexiones simultaneas. Reutiliza conexiones → mas eficiente bajo carga.
B — Directa 5432 Scripts puntuales, migraciones, consultas manuales. Conexion directa sin intermediario.

Para el job de sincronizacion Siesa que correra 3 veces al dia se recomienda Opcion A (Pooler).
