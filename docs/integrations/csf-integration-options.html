Integración CSF ERP → Portal C-Krea

Análisis de opciones de conexión · Documento de trabajo interno · Abril 2026

INTERNO CONFIDENCIAL

Contexto del problema

El Portal C-Krea necesita acceder a los datos del ERP CSF (recaudo, cartera, pagos) para reemplazar el proceso manual de Excel. IT ya nos suministró una API Key y el endpoint de prueba:

Endpoint: http://190.61.31.78:8099/api/v1/reportes/recaudo-cartera/
Auth: Authorization: Api-Key [CLAVE]

Problema central: La IP 190.61.31.78 es privada — solo accesible desde dentro de la red interna. El portal vive en Vercel (internet público) y no puede conectarse directamente. Esta hoja resume las alternativas evaluadas, ordenadas de más a menos segura.

Por qué no podemos conectarnos hoy
⚠ El bloqueador central

La API de CSF vive en la IP 190.61.31.78 — una dirección privada, solo visible dentro de la red interna. El portal de C-Krea está alojado en Vercel, servidores en internet que no tienen acceso a esa red. Es como intentar llamar a un teléfono interno de oficina desde afuera del edificio — la línea simplemente no conecta.

✓ Computador local (desarrollador)

Con OpenVPN activo, el computador del desarrollador sí puede conectarse a la API. Podemos construir y probar toda la integración localmente. Solo el desarrollador ve los resultados en su pantalla.

✗ Vercel (producción — usuarios reales)

Los servidores de Vercel están en un datacenter en internet. No tienen VPN. Cuando un usuario real abre el portal en vivo e intenta ver datos de CSF, la conexión falla — Vercel no puede llegar a la IP privada.

Qué significa esto en la práctica: Podemos construir toda la integración ahora y probarla en local. Pero para que funcione en el portal real que usan los administradores, necesitamos resolver el acceso de red — que es exactamente lo que las opciones abajo buscan solucionar. Sin resolver esto, la integración no puede ir a producción.

Opciones evaluadas — ordenadas por seguridad
🥇

Opción 1 — IT empuja datos a Supabase

IT configura un script que exporta datos del ERP a nuestra base de datos en la nube

Seguridad: Alta
ERP CSF → Script IT (programado) → Supabase (nuestro DB) → Portal C-Krea

IT instala un script en un servidor dentro de su red. Ese script se ejecuta automáticamente (cada noche, o cada hora) y empuja los datos relevantes hacia nuestra base de datos Supabase. La red interna de CSF nunca recibe conexiones del exterior — la puerta solo se abre desde adentro hacia afuera. Es como un empleado que saca información del banco y la deposita en nuestra caja; el banco nunca le abre la puerta a nadie externo.

✓ Ventajas

  • Red interna CSF nunca expuesta
  • Si nuestro portal es hackeado, atacante no llega al ERP
  • IT controla exactamente qué datos salen
  • Sin hardware adicional de nuestra parte
  • Más simple de auditar y monitorear

✗ Consideraciones

  • IT debe escribir y mantener el script
  • Datos con retraso según frecuencia del script
  • Requiere coordinación continua con IT

Qué necesitamos de IT

  • Script que lea del ERP y escriba en Supabase (les damos el connection string)
  • Definir frecuencia: ¿cada noche? ¿cada hora?
  • Confirmar qué tablas/campos pueden exportar
🥈

Opción 2 — IT expone la API con lista blanca de IPs

IT abre la API al público pero restringida a las IPs fijas de Vercel

Seguridad: Media-Alta
Vercel (IP fija) → Firewall CSF
(verifica IP + API Key) → API CSF ERP → Portal C-Krea

IT expone la API en una URL pública pero configura el firewall para que solo acepte conexiones desde las IPs de Vercel Pro. Aunque tengas la API Key, si tu conexión viene de otra IP, el firewall la bloquea. Son dos candados: Key + dirección IP. Si la Key se filtra, igual nadie puede usarla sin estar en la lista de IPs aprobadas.

✓ Ventajas

  • Conexión directa, datos en tiempo real
  • Sin hardware ni scripts adicionales
  • Doble autenticación (IP + API Key)
  • Fácil de revocar si es necesario

✗ Consideraciones

  • IT debe abrir un puerto en el firewall
  • Requiere Vercel Pro (IPs fijas)
  • Servidor ERP recibe tráfico externo
  • Si Vercel cambia IPs, hay que actualizar lista

Qué necesitamos de IT

  • Habilitar acceso público al endpoint de la API
  • Agregar las IPs de Vercel Pro a la lista blanca del firewall
  • Confirmar si pueden limitar por IP desde su lado
🥉

Opción 3 — Computador relay 24/7 con OpenVPN

Un computador siempre encendido actúa como puente entre Vercel y la red interna

Seguridad: Media
Vercel → PC Relay
(OpenVPN activo) → VPN Interna CSF → API ERP

Un computador viejo se deja encendido 24/7 (en la oficina o en casa), conectado siempre a la VPN de CSF. Ese computador corre un pequeño servidor proxy: cuando el portal necesita datos, le pregunta al relay, y el relay le pregunta al ERP por la VPN. El relay actúa como "traductor" entre el internet público y la red interna. Recomendación: ubicar el equipo directamente en la red del edificio para eliminar la dependencia de la VPN.

✓ Ventajas

  • No requiere cambios en la infraestructura de IT
  • Podemos implementarlo solos
  • Bajo costo (computador ya existe)
  • Si está en red local, no necesita VPN

✗ Consideraciones

  • Si el computador se apaga, portal pierde acceso
  • Requiere mantenimiento físico
  • Si el relay es hackeado, atacante entra a la VPN
  • Depende de internet estable en la ubicación

Qué necesitamos de IT

  • Credenciales VPN para el computador relay (si no está en red local)
  • O: un punto de red en las instalaciones para conectar el equipo directamente
⚠️

Opción 4 — Servidor VPS en la nube con VPN (no recomendada)

Servidor alquilado en internet con VPN instalada actúa como relay

Seguridad: Baja
Vercel → VPS Público
(internet + VPN) → VPN Interna CSF → API ERP

Similar a la Opción 3 pero usando un servidor alquilado en la nube (~$5/mes). El problema: este servidor está expuesto al internet público y tiene credenciales VPN de una red empresarial grande. Si ese servidor es comprometido por un atacante, el atacante obtiene acceso VPN a toda la red interna de CSF. No se recomienda para conectar a un ERP corporativo.

✓ Ventajas

  • Siempre encendido (no depende de hardware físico)
  • Bajo costo mensual (~$5 USD/mes)

✗ Consideraciones críticas

  • Servidor público + credenciales VPN = riesgo alto
  • Si hackeado, acceso total a red interna CSF
  • IT debe aprobar instalar VPN en servidor externo
  • Violación potencial de políticas de seguridad corporativa

Qué requeriría de IT

  • Credenciales VPN para dispositivo externo (muy probable que no lo aprueben)
