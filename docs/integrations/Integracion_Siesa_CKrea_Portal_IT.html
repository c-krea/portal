Parte 1
Resumen Ejecutivo

El Portal C-Krea y las aplicaciones en desarrollo necesitan datos de recaudo, cartera y pagos del ERP Siesa. Hoy dependemos de un computador local + OpenVPN, lo cual no es escalable para produccion. Como ya acordamos, la solucion es que IT programe un job automatico que empuje esos datos hacia nuestra base Supabase (PostgreSQL) 3 veces al dia (manana, medio dia, fin de jornada — igual que Power BI).

Lo que entregamos en este documento:

Connection string de Supabase, schema y tablas destino, y toda la documentacion tecnica necesaria para que IT pueda proceder.

2.2  Connection Strings para IT (usuario dedicado)

Usuario: siesa_sync — rol creado exclusivamente para el job de sincronizacion. Tiene permisos de SELECT, INSERT y UPDATE unicamente. No es superusuario.

Opcion A — Pooler (RECOMENDADA para jobs externos):

postgresql://siesa_sync:[PASSWORD]@aws-0-us-east-1.pooler.supabase.com:6543/postgres

Opcion B — Conexion directa:

postgresql://siesa_sync:[PASSWORD]@db.bosylehvmtwtqkrlievy.supabase.co:5432/postgres
Nota de seguridad

La contrasena se entregara por canal seguro (mensaje directo, Teams o llamada). No usar el usuario "postgres". El rol siesa_sync tiene solo los permisos necesarios para la sincronizacion.

2.5  Tabla de log de sincronizacion

La tabla siesa_sync_log ya existe y esta disenada para que el job registre cada ejecucion. IT puede insertar un registro cada vez que corra la sincronizacion con los campos: direction (push), entity_type (ej. 'payments'), status (pending / in_progress / success / error), y error_message si aplica.

2.6  Arquitectura de integracion

Flujo actual (lo que estamos solicitando):
ERP Siesa (on-premise)  →  job IT 3x/dia  →  Supabase (PostgreSQL cloud)  ←  Portal C-Krea (Vercel)

2.7  Notas tecnicas para el job de sincronizacion

  • Metodo recomendado: UPSERT (INSERT ... ON CONFLICT UPDATE) para evitar duplicados. Usar siesa_row_id o siesa_docto como clave unica.
  • Formato de periodo: Las tablas usan formato YYYY-MM (ej. '2026-04').
  • Multi-empresa: Cada registro necesita un company_id (UUID). El company_id de C-Krea se proporcionara junto con la contrasena.
  • RLS (Row Level Security): Las tablas tienen RLS activado. El job debe conectarse con el service_role key (no la anon key) para bypass de RLS, o se puede crear un rol PostgreSQL dedicado.
  • Pangea: Si la empresa ya trabajo con Pangea (integradores Siesa), ellos podrian facilitar la extraccion de datos del ERP.
